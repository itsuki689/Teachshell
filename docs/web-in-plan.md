# 教学网站更新：访问验证与功能方案

2026-10-28 文档复核：以下为原生 Swift 的历史方案/验收档案，包含当时的应用路径及实验步骤，不能作为本次操作授权或 Electron 当前行为。当前实现使用 Chromium、显式审核、可选登录记忆和默认关闭的后台巡检；见[使用指南](usage.md)、[批量审核](electron/teaching-batch-migration.md)及[文档目录](README.md)。始终保留原生课屿。

日期：2026-10-21

分支：`codex/web-in`

目标网站：[南京大学教学支持系统，课程 411](https://selearning.nju.edu.cn/course/view.php?id=411)

以下为最初规划。已实现的范围、验证结果和剩余工作见 [实施进度](web-in-progress.md)。

## 本次已验证的内容

- Codex 内置浏览器能访问网站，但未登录时课程链接会跳到网站登录页。登录页提供南京大学统一身份认证入口；用户尝试认证失败，怀疑被阻止。目前不能确定具体原因，已停止操作该浏览器的登录流程。
- 用户确认 Safari 可以正常登录。随后通过 Safari 原生界面检查了已经登录的课程页面，课程名为「数据库系统概论」，网站标记为 2026 年课程。
- 课程主页按「通知、课件、作业、实验」分区。课件包含章节文件夹；作业和实验链接指向独立的作业详情页。
- 第一章文件夹中有 `ch00.pptx` 至 `ch07.pptx` 的独立下载链接，以及「下载文件夹」按钮。已试下载 `ch00.pptx` 至系统下载目录，文件为 9,702,552 字节，PPTX 包结构及 ZIP 校验通过。
- 作业 09（活动 ID 5302）的详情页显示「到期日期：2026年10月26日 Monday 18:00」。这是网站显示的时间，正式同步前还须核对网站时区。
- 实验 lab2（活动 ID 5721）包含实验说明、独立的「实验手册二.pdf」附件链接及到期日期。只核实了附件入口，未试下载此附件。
- 网站的完成状态标记框与作业详情的提交状态是不同信息。同步时必须区分，不能直接把一个勾选框当成已交作业。

本次没有向正式资料库导入课程资料或创建计划，没有修改网站上的作业提交或完成标记。试下载的单份课件保留在 Downloads。未验证完整课程遍历、其他课程页面、跨会话登录、应用内 WebKit 登录或自动同步；也未验证网站是否开放可用的官方 API。

## 使用方式

第一次使用：在课程中选择「连接教学网站」，登录后选择网站课程，绑定到现有的本地课程。先展示网站课程名、学期和目标课程；不单凭名称自动创建重复课程。可选择同步课件、作业、实验及其附件，并预览初次导入范围。

完成连接后，课程页面提供一个「更新」按钮，旁边显示上次更新时间。按下后自动检查、下载、归类和更新计划；普通新增内容无需逐项确认。完成后显示例如「新增 3 份课件、2 项作业，1 项截止时间变更」，点击可查看详情并跳到相应资料或计划。

有本地修改冲突或时间不明确的项目单独列为「待处理」，其余明确的内容继续更新。可取消更新；中断后重试只处理尚未成功的项目。以后可在连接管理中对多门已绑定课程「全部更新」。

本阶段做访问验证和方案，不增加一个尚不能工作的更新按钮。

## 课件与文件夹

沿用网站的分区和文件夹层级，不根据文件名猜测章节。例如该课程第一章实际含有多份 `chXX.pptx`，应保留网站的「第一章」分组。

建议在本地课程资料中建立一个来源根目录：

```text
数据库系统概论（现有本地课程）
└── 教学网站
    ├── 课件
    │   ├── 第一章
    │   │   ├── ch00.pptx
    │   │   └── …
    │   └── …
    ├── 作业
    │   └── 作业09（有附件时保存附件）
    └── 实验
        └── lab2
            └── 实验手册二.pdf
```

这是资料库中的逻辑文件夹；文件内容仍通过现有的课程资料存储规则入库。不要把资料逻辑分组和 Finder 中的磁盘目录混为一谈，也不要把教师附件与自己的作业成果混放。

- 文件类别分别为课件、作业附件、实验资料；章节与作业名用文件夹表达。
- 保留文件原名、网站来源入口及活动关联；下载成功并验证内容后才成为正式资料记录。
- 同名文件通过来源身份区分；同一活动中的同一文件再次更新不产生重复记录。
- 下载目录可能变化，不能沿用当前按本地 `sourcePath` 去重的规则。需要独立的网站来源映射和内容指纹。
- 首次连接时，已手动导入的文件可经内容比对后由用户确认关联；不能仅因文件名相同就覆盖或合并。
- 教师替换文件时保留旧版，最新资料保持同一关联身份。若用户已修改本地内容，则保留两份并提示处理。
- 用户改过的名称、颜色、自定义顺序、备注和分组保留；只有仍由网站管理的分组跟随网站移动。

## 作业计划与 DDL

每个网站作业或实验对应一个固定计划，关联本地课程、原网页、题目说明和下载的附件。同一活动更新同一个计划。

- 网站有明确截止时间：填入计划的截止时间，沿用现有计划系统自动生成 DDL。不能再额外创建一条独立 DDL 任务，避免重复。
- 网站没有执行时段：不自动把计划塞进周视图时间格，不把发布时间或截止时间当成开始时间。用户可另行安排自己的执行时间。
- 月视图继续默认显示 DDL；日视图在相应日期置顶展示截止事项，周视图沿用现有显示规则。
- 导入的计划属于固定计划，编辑与拖动遵守现有「编辑固定计划」开关。用户自己安排的活动计划按原规则操作。
- 没有截止日期时保留待完成计划并标记未设置 DDL；仅有日期时按全天截止；含糊的自然语言日期留待确认。
- 截止时间优先取作业详情中的明确字段，区分截止、关闭提交、发布时间和最后修改时间。老师在通知中写的「某日之前」仅作为待核对提示。
- 日期转换必须明确网站显示时区，按绝对时间存储，再适配应用当前显示；保留原始日期文字以便核对。
- 已过期的历史作业在首次预览中默认排除，可手动纳入；未来尚未完成的作业默认加入。没有日期的作业单独分组供核对，不能静默遗漏。
- 网站「已提交」与本地「已完成」分别记录；初次同步可据明确的提交状态设置建议，后续不擅自撤销用户的完成状态。
- 本地调整过截止时间时，网站新日期作为变更提示，供选择采用网站时间或保留本地时间；不要静默覆盖。

## 更新时发生什么

1. 检查当前登录状态与已绑定账号、课程。登录过期则暂停并打开官方登录页，用户完成验证后继续。
2. 读取课程分区及活动目录，再读取文件夹、作业、实验的必要详情。通知中的「课件已更新」可辅助提示，不能替代真实文件列表和作业详情。
3. 按站点、账号绑定、课程 ID、活动类型、活动 ID 及文件身份比较上次结果，识别新增、修改、未变和暂时不可见的内容。
4. 文件先下载到暂存区，核对响应和实际内容，拒绝把登录页 HTML 当作 PPTX/PDF 入库。无变化时在网站提供可靠版本信息的前提下跳过重复下载；缺少版本信息时需要重新校验，不能保证零流量。
5. 按项目提交文件、分组、计划及来源映射。一个项目失败不让已成功项目重建；计划有明确 DDL 但附件失败时可保留计划，并显示附件待重试。
6. 保存更新记录和处理结果。课程扫描失败或页面只加载一部分时，不据此认定其他资料已被删除。

网站条目消失、权限变化或作业撤回时，保留本地资料与计划并提示来源变化，不自动清除用户的文件和成果。用户主动删除或忽略的网站条目需要记录为已忽略，后续更新不反复恢复；可在连接管理中重新加入。

## 登录与下载路线

已确定：不能把 Codex 内置浏览器登录失败直接等同于课屿内 WebKit 一定失败；也不能把 Safari 登录成功等同于课屿已经拥有该会话。

推荐先做一个小范围认证验证，再决定正式接入方式：

| 路线 | 使用体验 | 待验证内容 |
| --- | --- | --- |
| 课屿内独立 WebKit 登录 | 用户在官方网页手动登录并完成验证，应用保留会话；以后从课屿按更新 | 学校是否接受该环境、持久登录及重新登录、真实附件下载 |
| Safari 扩展桥接 | 用户在正常 Safari 登录；启用仅针对教学站点的扩展后，课屿按更新触发浏览器侧读取和下载 | 扩展消息与下载链路、Safari 开启条件、签名分发及站点权限 |
| 站点官方接口 | 若该账号确有可用且允许使用的接口，可降低页面解析依赖 | 目前没有验证，不能当作现成能力 |

第一条可复用项目现有 WebKit 导入经验，但应创建独立的教学网站连接，使用可保留会话的数据存储；现有本科课表导入器采用临时会话，不能直接充当此功能。账号切换时暂停原绑定，重新确认后再同步。

如第一条认证确实不兼容，优先验证 Safari 扩展方案，而不是重复模拟登录。Apple 提供 macOS 应用与 Safari Web Extension 的双向消息机制，因此可以保留「在课屿按更新」的目标；但它需要浏览器与扩展可用，不能保证 Safari 完全关闭时仍能更新。

应用内登录与 Safari 会话相互独立。Safari 侧方案应在浏览器自己的会话中获取资料，通过本地消息交给课屿，不以复制用户 Cookie 作为常规产品流程。账号密码由官方网页登录处理，不写入资料库、计划说明或调试日志；会话也不随资料库备份导出。

## 实施顺序与验收

1. **认证与下载验证**：先只连接课程 411，验证应用内登录、重开应用后的会话、单份课件和单份作业附件下载。若认证失败，转做 Safari 桥接验证。此阶段使用隔离资料库。
2. **单课程完整更新**：实现分区扫描、章节文件夹、附件入库、固定计划与自动 DDL；以真实课程样例和脱敏测试样例核对结果。
3. **重复更新与冲突处理**：验证重复点击不增加副本，教师改名/替换文件/延期，本地改名/移动/改 DDL，删除后忽略，登录失效和中途失败恢复。
4. **多课程与正式入口**：绑定更多课程，逐门确认目标课程，加入全部更新、更新记录及重试；通过界面验证后再接入正式资料库。

验收应包括：相同输入第二次更新新增数为零；附件确为可打开的原文件；文件夹与网站一致；作业 09 的明确截止时间能映射到 DDL；无执行时间不占据周视图时间格；本地修改及完成状态保留；登录失效时不导入 HTML 或清空已有内容；中断后重试不重复创建。

目前不需要用户提供账号密码。真正需要补充的是应用内登录验证的结果、以后要绑定的课程，以及首次同步历史作业的范围；这些应在连接流程中完成。
